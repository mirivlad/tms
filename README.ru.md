# TMS

TMS — лёгкая self-hosted система управления задачами для тех, кто хочет хранить задачи и данные на собственной инфраструктуре.

> **Текущий стабильный релиз:** `v0.2.2`

```text
ghcr.io/mirivlad/tms:v0.2.2
```

Тег `latest` указывает на последний стабильный релиз. Для воспроизводимой установки рекомендуется фиксировать конкретную версию. Проверенные CI сборки из `main` публикуются как `edge` и неизменяемые теги `sha-<commit>`.

## Что умеет TMS

- несколько изолированных пользователей;
- список задач, Kanban-доска и календарь;
- быстрое создание задач, форматированное описание и вложения;
- статусы, типы задач, заказчики и типизированные пользовательские поля;
- личные и командные проекты с файлами, собственными статусами задач и пользовательскими полями;
- команды с ролями lead/member, приглашениями и назначением ответственных;
- обсуждения проектов и задач с ответами, `@упоминаниями` и внутренним inbox уведомлений;
- расширенные фильтры, сортировка, пагинация и массовые операции;
- язык, часовой пояс и тема отдельно для каждого пользователя;
- опциональная самостоятельная регистрация и подтверждение администратором;
- уведомления по SMTP/email;
- Telegram через **Long polling** или **Webhook**, с HTTP/SOCKS-прокси и пользовательской проверкой доставки;
- восстановление пароля через браузер или локальную консоль;
- автоматические миграции MariaDB, Docker Compose и шаблон для Portainer;
- образы для `linux/amd64` и `linux/arm64`.

## Быстрый запуск готового образа

Скопируйте `.env.example` в `.env`, задайте как минимум `DB_PASS`, `APP_URL`, `APP_TIMEZONE`, `APP_LOCALE` и `SESSION_SECURE`, затем запустите:

```bash
docker compose -f compose.portainer.yaml up -d
```

Создайте первого администратора:

```bash
docker compose -f compose.portainer.yaml exec app php bin/create-admin.php admin admin@example.com
```

Откройте `APP_URL` и войдите. Настройка reverse proxy/TLS, Portainer, обновление, backup и полный список переменных описаны в [руководстве по установке](docs/INSTALLATION.ru.md).

## Основные принципы

- self-hosted в первую очередь;
- никакой логики тарифов, подписок и trial;
- никаких production-секретов и пользовательских данных в репозитории;
- данные пользователей изолированы по умолчанию;
- изменения схемы только через миграции;
- проверки безопасности находятся на повторно используемых границах, а не только в контроллерах;
- стабильные релизы публикуются только после CI.

## Локализация

Интерфейс поставляется на русском и английском языках. `APP_LOCALE=en|ru` задаёт язык установки по умолчанию. Авторизованный пользователь может переключить язык в интерфейсе; выбор в сессии имеет приоритет.

Начальные статусы и типы задач нового пользователя создаются на языке установки. Уже существующие пользовательские названия при переключении интерфейса автоматически не переименовываются.

## Разработка из исходников

```bash
cp .env.example .env
composer install
php bin/migrate.php
php bin/create-admin.php admin admin@example.com
composer check
php -S 127.0.0.1:8080 -t public
```

Эталонным окружением для интеграционных проверок остаётся Docker/Apache. `composer.lock` хранится в репозитории, поэтому CI и релизы используют одну базу зависимостей.

## Безопасность

TMS использует CSRF-защиту браузерных изменений, owner scope для приватных сущностей, параметризованные SQL-запросы, защищённое хранение вложений, безопасные session/remember-токены и шифрование секретов уведомлений. Release-blocking инварианты описаны в [SECURITY.md](SECURITY.md).
