# MCP OAuth в TMS 0.6.1

TMS включает собственный сервер авторизации для удалённого MCP Streamable HTTP. Ручные Bearer-токены сохраняют права, сроки и квитанции операций. OAuth — дополнительный способ подключения, а не обязательная миграция. Каждый пользователь разрешает доступ к собственной учётной записи TMS.

## Развёртывание

APP_URL должен содержать точный публичный HTTPS origin (без пути, параметров и фрагмента), SESSION_SECURE=true. OAuth включён по умолчанию при HTTPS, а также на буквальном loopback HTTP для локальных тестов. MCP_OAUTH_ENABLED=false отключает OAuth-маршруты и приём OAuth access-токенов, не влияя на ручные токены. Повторное включение само по себе не отзывает ранее выданные разрешения; отзывайте их в профиле. Прокси должен передавать Authorization и маршрутизировать .well-known и /oauth в TMS; не записывайте тела запросов токенов и строки запроса с кодами авторизации в журнал. Рекомендуются ограничения частоты запросов на прокси по источнику для регистрации и авторизации, включая попытки ввода пароля, без нарушения перенаправлений. В приложении установлен общий дневной лимит регистрации 1000 клиентов (не строгая распределённая квота); зарегистрированные клиенты сохраняются. При регистрации сервер не загружает внешние URL.

## Подключение клиента

Укажите APP_URL/mcp, Streamable HTTP, OAuth и динамическую регистрацию клиента (DCR). Метаданные:
- GET /.well-known/oauth-protected-resource/mcp (также /.well-known/oauth-protected-resource)
- GET /.well-known/oauth-authorization-server

Неавторизованный запрос MCP получает HTTP 401 с WWW-Authenticate и resource_metadata. Метаданные содержат адреса регистрации, авторизации, выдачи и отзыва токенов. Регистрация — JSON с точными redirect_uris (HTTPS либо буквальный loopback HTTP), grant_types authorization_code и refresh_token, response_types code и token_endpoint_auth_method none, client_secret_basic либо client_secret_post. Имя клиента указывается самим клиентом, не подтверждает его подлинность. Не раскрывайте секрет конфиденциального клиента. CIMD и private_key_jwt не реализованы.

Запустите авторизацию с response_type=code, client_id, redirect_uri, scope, state, code_challenge и code_challenge_method=S256. Передавайте resource=APP_URL/mcp; отсутствие параметра трактуется только как этот единственный ресурс. TMS сверяет точный зарегистрированный redirect URI, показывает название клиента, адрес возврата и права, требует логин, пароль TMS и явное согласие либо отказ. Пароль клиенту не передаётся. Окно согласия действительно десять минут. Callback получает код, state (если передан) и issuer. Клиент должен сверить state и issuer. Код действует пять минут и привязан к клиенту, redirect URI, ресурсу и PKCE.

POST application/x-www-form-urlencoded на /oauth/token: grant_type=authorization_code, code, client_id, redirect_uri, code_verifier, resource и соответствующая авторизация клиента. Полученный access-токен передавайте в Authorization: Bearer. Он действует 3600 секунд. Обновление: grant_type=refresh_token, refresh_token, client_id, resource и авторизация клиента. Семейство refresh-токенов действует 30 дней с момента согласия. При обновлении меняются оба токена, предыдущий access-токен перестаёт действовать. Выполняйте обновления последовательно: повтор старого refresh-токена отзывает семейство. Повтор корректно связанного использованного кода в пределах его срока также отзывает разрешение. Обновление не расширяет права. Квитанции request_key сохраняются при ротации.

## Права

| Запрошенный scope | Фактические права |
|---|---|
| tms:read | 25 инструментов чтения |
| tms:write | Чтение и запись, 61 инструмент |
| tms:delete | Чтение, запись и удаление, 75 инструментов |

Без scope — только чтение. Удаление требует отдельного согласия на tms:delete; каждая разрушительная операция по-прежнему требует штатного подтверждения и прав на объект. Администрирование через MCP недоступно. При нехватке OAuth-прав на известный инструмент возвращается HTTP 403 с требуемым scope в WWW-Authenticate. Схемы и ошибки старых токенов совместимы.

«Профиль → Интеграции с ИИ (MCP)» показывает OAuth-подключения рядом с ручными токенами; в столбце срока для OAuth указан срок refresh-семейства. Отзыв отключает одновременно access и refresh. Клиент может также выполнить POST /oauth/revoke с token, client_id и соответствующей авторизацией клиента. Токены и пароли в открытом виде в БД не хранятся. Смена пароля автоматически не отзывает подключения, используйте явный отзыв.

## Статус совместимости

Реализация ориентирована на MCP 2025-11-25, discovery и OAuth authorization code + PKCE с DCR. Независимая сертификация соответствия и аудит безопасности не проводились. CIMD, OIDC, client credentials, device flow и другие grant types не реализованы. Прямое подключение веб-ChatGPT, его плагин и отдельные требования UI авторизации инструментов проверяются следующим этапом. Для текущей версии нужен клиент с DCR; старые клиенты Bearer не требуют изменений.

Тест tests/smoke/mcp_oauth.py выполняется на изолированной установке с APP_URL, MCP_TEST_USER, MCP_TEST_PASSWORD, MCP_FOREIGN_USER, MCP_FOREIGN_PASSWORD и MCP_WRITE_TOKEN. Используются временные учётные записи; тест не предназначен для боевого сервера.
