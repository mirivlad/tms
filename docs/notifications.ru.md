# Уведомления и Telegram

TMS использует общий механизм уведомлений для email и Telegram. Системные транспорты настраивает администратор, а правила доставки выбирает каждый пользователь.

## Пользовательские правила

В **Настройки → Уведомления** можно включить email и/или Telegram и выбрать:

- задачи на завтра;
- приближающиеся сроки с упреждением по приоритету;
- просроченные задачи;
- ежедневный дайджест.

Успешные отправки записываются в `sent_notifications` с дедупликацией отдельно по каналам. Сбой одного канала не подавляет другой.

Фоновый планировщик сейчас рассчитывает заданное время отправки по `APP_TIMEZONE`.

## Ключ шифрования

SMTP-пароль, token Telegram-бота, webhook secret и URL proxy шифруются libsodium до записи в БД.

По умолчанию TMS создаёт 32-байтовый ключ в `/var/www/html/var/secrets/notification.key`; он сохраняется в volume `tms-secrets` и совместно используется `app`, `notifier` и `telegram-poller`.

Вместо него можно задать внешний `NOTIFICATION_SECRET` — base64 от 32 случайных байт:

```sh
php -r 'echo base64_encode(random_bytes(32)), PHP_EOL;'
```

Не меняйте существующий ключ без готовности заново ввести зашифрованные реквизиты. Ключ резервируется вместе с БД.

## SMTP

SMTP настраивается в **Администрирование → Системные уведомления**. До включения рабочих уведомлений используйте встроенную отправку тестового письма.

## Настройка Telegram-бота

1. Создайте бота через BotFather.
2. Введите username и token в **Администрирование → Системные уведомления**.
3. Сохраните и нажмите **Проверить соединение с Telegram**.
4. Если прямой доступ к `api.telegram.org` отсутствует, настройте proxy Telegram.
5. Выберите **Long polling** или **Webhook**.

`TELEGRAM_BOT_NAME`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `TELEGRAM_PROXY_ENABLED`, `TELEGRAM_PROXY_URL` остаются опциональными bootstrap/fallback переменными. Основной способ настройки — web-админка.

### Long polling

Long polling рекомендуется по умолчанию. `telegram-poller` вызывает Telegram `getUpdates`, при необходимости через настроенный proxy. Следующий `update_id` хранится в MariaDB, поэтому после рестарта уже обработанные события не повторяются.

При переходе в polling worker выполняет `deleteWebhook` **без удаления pending updates**, затем забирает их через polling. Входящее соединение Telegram к серверу TMS не требуется.

На одну БД должен работать один polling worker. Дополнительно worker берёт advisory lock MariaDB, защищаясь от случайного второго consumer.

### Webhook

Webhook требует публичный HTTPS `APP_URL`. Настройте/сгенерируйте webhook secret, выберите Webhook и нажмите **Установить webhook Telegram**. Telegram будет отправлять события на:

```text
APP_URL/telegram/webhook
```

TMS проверяет `X-Telegram-Bot-Api-Secret-Token`. Если Telegram не может достучаться до endpoint, используйте Long polling.

### Proxy Telegram

Поддерживаются `http://`, `https://`, `socks5://`, `socks5h://`.

Схема означает протокол самого proxy. Для обычного HTTP CONNECT proxy пример будет таким:

```text
http://172.17.0.1:1081
```

То, что Telegram использует HTTPS, не превращает HTTP proxy в `https://`.

Proxy применяется для проверки API, исходящих сообщений, регистрации/удаления webhook и Long polling.

## Привязка пользователя

Пользователь открывает **Настройки → Уведомления**, генерирует одноразовую команду `/link_...` и отправляет её боту. Команда живёт 24 часа, используется один раз; в БД сохраняется только SHA-256 hash verifier.

После успешной привязки бот отвечает подтверждением, а TMS сохраняет chat пользователя. Затем рекомендуется нажать **Отправить тестовое сообщение** в TMS и проверить полный путь доставки.

## Фоновый notifier

Docker/Portainer сервис `notifier` запускает `php bin/notify.php` каждые `NOTIFICATION_INTERVAL_SECONDS` секунд (по умолчанию 60).

При нативной установке используйте cron для `bin/notify.php`. Не запускайте несколько независимых scheduler без необходимости: дедупликация защищает уже успешные записи, но параллельные процессы теоретически могут одновременно начать внешнюю отправку до фиксации успеха.
